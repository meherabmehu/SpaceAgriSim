# Local development / test dependencies
-r requirements.txt
pytest>=8.0
# Starlette's TestClient prefers `httpx2` when it is installed and emits a deprecation warning for
# the `httpx` compatibility shim when it is not. The warning came from fastapi.testclient, not from
# this project's code, but it printed on every run of a 1 235-test suite and made a real warning
# indistinguishable from noise. Declared here (test tooling only, never in the runtime image) so the
# suite is quiet by construction rather than by a filter.
httpx>=0.27
httpx2>=2.16,<3.0

# The phase 7-11 tests exercise the analysis scripts directly (calibration, uncertainty, model
# reproduction), so the scientific stack those scripts import is a test dependency, not just a
# training-time one. Without these, collection aborts on a clean runner while a developer
# machine that happens to have them installed looks fine.
numpy>=1.26
pandas>=2.1
scipy>=1.11
scikit-learn>=1.4

# PDF text extraction for the quote-verification tests (phase 16/18). Without it those checks
# skip silently, which is how a quote can drift from its source without anyone noticing.
pymupdf>=1.24

# The phase 30 dataset gate shells out to `ml/research/build_phase30_datasets.py --check`, which
# reads the two acquired workbooks with openpyxl. It was pinned in `ml/requirements-training.txt`
# (the training stack) but not here, so a clean runner failed two dataset tests at import while a
# developer machine that already had it passed - the worst kind of difference between two
# environments running the same suite.
openpyxl>=3.1,<4
