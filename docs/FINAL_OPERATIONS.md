# Final operations report — CI, repository hygiene, and what was not touched

The repository is now guarded by CI in the places where it previously relied on memory. That is the
main operational change in this pass; the rest of this document records the two hygiene mechanisms
that Phase 35 introduced and that this pass verified still work, and the deployment boundary that was
held.

## 1. Continuous integration

Five jobs, all green locally in the same order. `.github/workflows/ci.yml`:

| Job | What it does | What it did before this pass |
|---|---|---|
| `backend` | installs `requirements-dev.txt`; runs `pytest -q backend/tests` on SQLite; `pip-audit` on **both** requirement files; `bandit -q -r backend/app` | audited only the runtime pins; no static analysis |
| `postgres` | PostgreSQL 17 service; runs the suite against it and **fails if any test skips** | unchanged |
| `science` | **new** — nine read-only gates: model audit (writes only with `--write`), registry verification, provenance, feature readiness, coverage, gap matrix, Phase 34 measurement sync, Phase 35 verdicts, screenshot dedupe | did not exist: every one of those gates was manual |
| `frontend` | lint, typecheck, **`build:check`**, `npm audit --audit-level=high` | ran `npm run build`, which passes even when the bundle guard fails |
| `browser` | Playwright across three viewports | unchanged (now 156 tests, was 150) |

Two consequences worth stating plainly:

* a model card that stops matching its evaluation file now **fails the build**, instead of waiting for
  someone to run the audit script;
* a change that pushes the initial request over 240 kB, or introduces an import cycle, or produces an
  oversized chunk, now **fails the build**, instead of being visible only to whoever ran
  `npm run build:check` by hand.

`scripts/verify_model_registry.py` gained `--check` for exactly this reason: the CI gate must be able
to verify without rewriting `docs/phase7/registry_verification`. A timestamp-only diff in that
file had twice been mistaken for a real change, which is the cost of a gate that cannot run read-only.

## 2. Screenshot store

115 committed screenshots held only 53 unique images — a capture that does not change was copied into
each phase's baseline, candidate and parent directories, 46.9 MB of exact duplication.

`ml/research/dedupe_screenshots.py` keeps one canonical copy per image, records every removed path in
`docs/screenshots/MANIFEST` with the SHA-256 it shares with the canonical file, and `--check`
fails if a duplicate reappears. The drift scripts resolve a removed path through the manifest, so they
still compare the same pixels and still report 0.000 % for a capture that was merely duplicated, marking
the row `identicalCopyOf`.

`docs/screenshots` is now 25 MB, and the `science` job verifies it on every push. Verified in this
pass: `53 unique images, 46.9 MB of duplicates recorded`.

## 3. Checkout recovery

Some execution environments snapshot the workspace with a size budget; a repository larger than that
budget can come back without its `.git` directory. It happened again at the start of this pass: 144
tracked deletions, 6 modified scripts and 8 missing screenshots appeared in a tree that had been clean.

`scripts/restore_git.sh` reattaches the tree to the remote without overwriting a single file: it clones
history into a temporary directory, moves `.git` into place, resets the index with `--mixed` so local
edits appear as modifications rather than disappearing, strips any credential from the remote URL, and
prints what differs. It was tested against a copy with an injected edit; the edit survived.

The procedure that was actually used, and that works:

```bash
SPACEAGRISIM_GIT_TOKEN=… bash scripts/restore_git.sh https://github.com/meherabmehu/SpaceAgriSim.git main
git checkout -- .          # restores files the snapshot dropped
git status                 # must be clean apart from work in progress
```

Files regenerated by the dedupe-sensitive capture steps reappear as untracked after a re-run; they are
deleted rather than committed, and `dedupe_screenshots.py --check` is the test for it.

## 5. Test-tooling change worth naming

`backend/requirements-dev.txt` now pins `httpx2`. Starlette's `TestClient` prefers it and emits a
`StarletteDeprecationWarning` through `fastapi.testclient` on every run of a 1 235-test suite when it is
absent. The warning came from the library, not from this project, but a warning that prints on every
green run is how a real warning becomes invisible. Declared as a test-only dependency rather than
filtered in `pytest.ini`: the suite is quiet by construction, and no warning was suppressed.

## 6. Reproducing a delivery

1. `git ls-remote origin refs/heads/main` — record the SHA being delivered.
2. Fresh clone of that SHA; `git config user.name` / `user.email` set before any commit.
3. Create the phase branch from that SHA, never from a local tree.
4. Run every gate in `docs/FINAL_QUALITY_GATES.md` on the final tree.
5. Commit, push the branch, fast-forward `main` only if the branch is a strict descendant.
6. Re-read the remote refs with `git ls-remote`, and verify with a fresh depth-1 clone that the files
   are the ones that were tested.

Step 6 is not ceremony: this repository has twice come back from a snapshot with files missing.
